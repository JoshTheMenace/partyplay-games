# Blockwild 2: design contract

This document supersedes every earlier Blockwild design note. The game is a ground-up rebuild: a cooperative first-person voxel survival sandbox for 1–64 players in the shared PartyPlay room (32 is the size it is tuned and measured for; see Big rooms). The goal is gameplay quality, not a checklist. Moving, mining and placing must feel instant; the world should look good (smooth lighting, glowing torches, real night, a long view distance); and survival should give casual party players a clear loop from punching trees to diamond tools, then on to villages, armor, redstone and the Nether, and finally an ending a party can reach together in a few sessions: Nether fortress → blaze rods → ender pearls → eyes of ender → stronghold → the End → defeat the Ender Dragon → a shared victory celebration, after which the sandbox continues.

A third mode, **Caper City** (2026-11), is a different game on the same engine: an open-world city sandbox with residents, vehicles, gigs and the Watch. It has its own section below; everything before that section describes the wild (survival and creative), which the city leaves untouched.

The game id stays `blockwild`, so both registries (`apps/party-server/src/registry.ts` and `apps/party-client/src/registry.ts`) keep working unchanged. `src/manifest.ts`, `src/server.ts` (`rules` plus a default export) and `src/client.tsx` (`client` plus a default export) stay at those paths. Survival and creative saves are format version 11 (9 and 10 still load); city saves are version 13 (12, the city's first, still loads). Older saves (format versions 1–8) are rejected with a clear message: "This world was made with the previous version of Blockwild and cannot be loaded."

Reuse from the old game: the host music playlist (`public/games/blockwild/music`, `music.ts`, `host-music.ts`), the licensed sounds in `public/games/blockwild/sounds` (keep the LICENSE files), and optionally the old GLB mob models as a fallback reference. Everything else is new. Delete old source, tests and markdown notes that no longer describe the game (BEDROCK-REFERENCE, CHUNKED-WORLDS, FARMING, SURVIVAL, SOUNDS, VERIFICATION) once the replacement exists. README.md is rewritten at the end.

## Platform facts every agent must respect

- Contract: `packages/party-contract/src/index.ts`, `protocol.ts`; UI: `packages/party-ui/src/index.ts`; Three helper: `packages/party-3d/src/index.ts`; runtime helpers (`ResourceScope`, `SnapshotBuffer`, `FrameMetrics`, `FixedStepClock`): `packages/party-runtime/src`. Read the real exports.
- Incoming messages are capped at 32 KiB; 80 messages/s/socket; **256 reliable actions per player per round**. A sandbox session far exceeds 256 actions, so **all gameplay commands travel inside held input** (see Networking). Do not use `sendAction` for gameplay; the `Action` type is only `{ type: 'noop' }`.
- Held input (`setInput`) is coalesced and resent at up to 20 Hz; latest wins. `releaseInput` maps to `rules.neutralInput()`.
- Outgoing views must be JSON-serializable with finite numbers; omit absent optional fields (never assign `undefined`).
- The Vite guard rejects only `src/server.ts` and `src/content.ts` from browser chunks. **Server-only code lives in `src/sim/` and must never be imported by `src/client/`, `src/client.tsx` or `src/shared/`.** A test enforces this (scan import specifiers).
- `parseInput` must tolerate garbage and partial objects (the platform test sends `{x:1,y:0}`): return a sanitized input, never throw on shape problems.
- `validateSettings({})` returns defaults.
- Save hooks: `exportSave`, `loadSave`, `finish`; manifest `sessionControls: ['save','finish']`. Saves must stay under 256 KiB (`MAX_SAVE_BYTES`) in the worst legal case. The server autosaves every 30 s.
- `snapshotCache: { revisionField:'revision', fields:['edits','who','ledger'], keyedPairsFields:['edits'] }` (`ledger` is Caper City's results table: an empty list in the wild and until a city round ends, see that section): `edits` is `[cellIndex, cellValue][]`, unique nonnegative integer pairs. The platform re-reads the whole list whenever `revision` changes, so `revision` moves only when the tail of recent edits is folded in (see Networking: the edit journal), never per edit.
- Never run Prettier. Match the terse house style, but prefer readable code over code golf: one statement per line in non-trivial logic, meaningful names. No `any` in exported APIs.
- No git staging/commits.

`prepareTimeoutMs` is 90 s because the room waits for every screen and fails the whole start when one misses the limit: with up to 64 phones one slow one is likely, and a world load makes every screen re-upload its cached terrain into a new GL context.
Client module: `immersivePhone: true`, `sceneRoles: ['display','controller']`.

## World

- Axes: +X east, +Y up, +Z south. 1 unit = 1 block = 1 m.
- `WORLD = 4096` (x,z in [0,4095]), `HEIGHT = 128` (y in [0,127]), `CHUNK = 16`, `SEA_LEVEL = 62`. Bedrock at y=0 (with a ragged layer to y≤3). Outside the world horizontally is an invisible wall; above 127 is air; below 0 is bedrock (air in the End: see below).
- Cell value = `id | (state << 8)` stored in `Uint16Array`; `id` 0–255 block id, `state` 0–255 block state. Column chunk storage is `Uint16Array(16*16*128)`, local index `lx + 16*(lz + 16*y)`.
- Global linear cell index (edits, saves): `x + WORLD * (z + WORLD * y)` (max < 2^31).
- Terrain is a pure deterministic function of `(seed, cx, cz)` shared by server and browser worker. **Determinism across V8 and JavaScriptCore:** use only `+ - * /`, `Math.floor`, `Math.sqrt`, `Math.abs`, `Math.min/max`, and integer hash functions (`Math.imul`, bit ops). Never use `Math.sin/cos/exp/pow/log/random` in worldgen.
- Edits: a sparse `Map<cellIndex, cellValue>` journal over generated terrain. Writing a cell back to its generated value deletes the entry. The journal is limited by what a save can hold, not by a fixed count: packed and deflated (`sim/journal.ts`) it must fit `EDIT_BYTES` = 100,000 bytes, with a hard ceiling of `EDIT_LIMIT` = 65,536 distinct cells. Walls, floors and tunnels pack to about a byte an edit, scattered single cells to seven, so tidy building reaches the ceiling while the worst journal stops near 32,000 (never before 16,384). `world.limit` is the current allowance (the measured size plus what the remaining bytes surely hold); it is re-measured only when it runs out. A command that would exceed it is rejected with the toast "This world has reached its building limit."
- World spawn: near (2048, 2048), searched outward (within 512 blocks) for grass with a tree within 12 blocks, else any dry grass/sand above sea level; never within 3 blocks of water or cactus, and eye height is clear for 2 blocks. Players spawn spread over the nearest free columns (121 candidates within 5 blocks, so a full room of 64 stands side by side), on the ground (never on a canopy).
- The Nether is a sealed corner of the same storage, not a second world: `x ∈ [3584, 4096), z ∈ [0, 512)` (`NETHER = { x0: 3584, z0: 0, size: 512 }`, `inNether(x, z)` in `shared/constants.ts`). "Dimension" is derived from position, so physics, raycast, edits, saves, lighting, meshing, networking and entities work unchanged. Bedrock walls fill column x = 3584 and row z = 511 at full height, with a ragged bedrock floor (y 0–4) and ceiling (y 123–127). The overworld around that corner is deep ocean (the nearest land is about 170 blocks from the walls).
- The End is another sealed corner: `x ∈ [3584, 4096), z ∈ [3584, 4096)` (`END = { x0: 3584, z0: 3584, size: 512 }`, `inEnd(x, z)`, and `dimensionAt(x, z): 'overworld' | 'nether' | 'end'` in `shared/constants.ts`). Below y = 0 it is the **void** (air, in `shared/chunk.ts` and the client engine alike), sealed horizontally by the world edge and invisible barrier columns along its inside faces (x = 3584 and z = 3584) that nobody can see or reach from the island. The overworld corner next to it is deep ocean.
- Day: `DAY_TICKS = 24000` at 20 ticks/s (20 minutes). Tick 0 = sunrise, 6000 noon, 12000 sunset, 13000–23000 night. New worlds start at tick 1000.

### Biomes and generation (worldgen owner)

Biomes from low-frequency temperature/humidity/continentalness noise: ocean, beach, plains, forest (oak+birch), birch forest, taiga (spruce, ferns), snowy tundra (snowy grass, ice on water, sparse spruce), desert (sand, sandstone underneath, cactus, dead bush), mountains/hills (stone peaks, snow caps above y≈105, exposed ores), swamp-ish river banks optional. Rivers carve through land. Smooth biome blending for height (no cliffs at biome borders). 3D cave systems (noodle/cheese style from 3D noise, plus a few ravines), ores by depth: coal (y 5–110, common, larger veins), iron (y 5–64), gold (y 5–32, rare), diamond (y 5–16, rare, small veins), clay patches in shallow water, gravel patches. Decorations: tall grass, ferns, flowers, sugar cane at water edges, pumpkins rare, melons rare in forests, trees per biome with varied heights and leaf shapes (oak balloon, birch tall, spruce cone). Trees must not be cut at chunk borders: decorate using a deterministic per-chunk feature pass that also considers features from neighbouring chunks within a 3-block margin. Expansion terrain: deep caves (y ≤ 9) fill with lava in about three regions out of four and water in the rest (never spilling into air); single emerald ores in mountain stone (y 5–100); redstone ore (y 5–16); rare sealed lava lakes in deserts and mountains, never near trees, villages or temples; world spawn avoids lava. `generateChunk` dispatches Nether chunks (`cx >= 224 && cz < 32`) to `generateNetherChunk` (shared/nether.ts, which then calls `paintFortress`), End chunks (`cx >= 224 && cz >= 224`) to `generateEndChunk` (shared/end.ts), and paints structures into overworld chunks (`paintStructures`, then `paintStronghold`, shared/structures). Strongholds and fortresses only touch chunks near them, so every other v9-generated chunk stays byte-identical (a golden-hash test over 407 overworld and Nether chunks guards this). Target: `generateChunk` ≤ 6 ms median in Node on a laptop (Nether chunks ≤ 8 ms; about 1.1 ms measured).

## Player physics (shared, `src/shared/physics.ts`)

Used identically by client prediction and server validation. AABB 0.6×1.8 (sneaking 0.6×1.5), eye height 1.62 (sneak 1.27). Gravity 32 m/s², jump velocity 9.0 (≈1.25 block jump), terminal velocity 78. Ground acceleration model with friction; walk 4.3 m/s, sprint 5.6, sneak 1.3 (sneak prevents walking off edges), creative flying 10.9 horizontal, fly up/down 7.5. Auto step-up is **off** (MC style: jump to climb), except slabs/half-height stairs (step height 0.6 is OK). Water: slow movement, sink slowly, hold jump to swim up; drowning handled by server. Ladders: climb at 2.35 m/s when moving into them or holding jump; sneak holds position. Axis-separated sweep against `collisionBoxes`, with sub-steps so nothing tunnels at terminal velocity. Deterministic given `(state, input, dt, getCell)`.

```ts
type Body = { x:number; y:number; z:number; vx:number; vy:number; vz:number; onGround:boolean; inWater:boolean; onLadder:boolean; sneaking:boolean; flying:boolean };
type MoveIntent = { forward:number; strafe:number; jump:boolean; sneak:boolean; sprint:boolean; flyDown:boolean; yaw:number };
function stepBody(body:Body, intent:MoveIntent, dt:number, getCell:(x:number,y:number,z:number)=>number, mode:'survival'|'creative'): void;
```

## Networking model (the core of "feels instant")

Server tick 20 Hz, snapshots 20 Hz. The server is authoritative for the world, inventories, health, mobs, items and every rule. The client is authoritative-with-validation for its **own position** so movement has zero latency.

### Input (held; `src/shared/protocol.ts`)

```ts
type Input = {
  p: [number,number,number]; v: [number,number,number]; yaw:number; pitch:number;
  f: number;           // flags: 1 onGround, 2 sneak, 4 sprint, 8 flying, 16 using-item (eating / drawing bow), 32 swinging
  slot: number;        // selected hotbar slot 0–8
  mine: [number,number,number] | null;   // block currently being mined (crack progress + timing validation)
  tpAck: number;       // last server teleport sequence this client applied
  cmds: Cmd[];         // every not-yet-acknowledged command, ascending n, at most 32
  bag?: number;        // the newest PrivateView.bag.rev this client holds (0 or absent = none)
};
type Cmd = { n:number } & (
  | { t:'break'; x:number; y:number; z:number }
  | { t:'place'; x:number; y:number; z:number; face:number; slot:number }     // x,y,z = the clicked block; face 0..5 = -X,+X,-Y,+Y,-Z,+Z
  | { t:'use'; x:number; y:number; z:number; face:number }                     // interact with a block (table, furnace, chest, bed, door, crop with bone meal, till with hoe, bucket)
  | { t:'useItem'; slot:number }                                               // finish eating, release bow, use bucket on air
  | { t:'attack'; id:number; part?:number }                                    // mob id; part = the dragon's hit box (server re-checks)
  | { t:'interact'; id:number }                                                // shear / feed / breed a mob
  | { t:'click'; w:'inv'|'grid'|'out'|'screen'; i:number; b:0|1|2 }           // left, right, shift-click (MC container semantics)
  | { t:'craft'; r:string; max?:boolean }                                      // recipe-book craft straight into the inventory
  | { t:'close' }                                                              // close screen; grid + cursor contents return to inventory
  | { t:'drop'; slot:number; all?:boolean }
  | { t:'respawn' }
  | { t:'wake' }                                                               // leave a bed
  | { t:'creative'; id:number; slot:number }                                   // creative: put a full stack of id into slot
  | { t:'trade'; i:number; max?:boolean }                                      // run offer i of the open trade screen once, or as often as possible
);
// click targets also include 'armor' (i = 0 head .. 3 feet); useItem with armor in hand equips it (swapping); attack also takes a ghast fireball's id (hitting sends it back)
```
`neutralInput()` keeps the last position semantics: the server ignores `p` from a neutral input (flag it with `f & 64` "no position" or compare with a sentinel) and treats it as standing still with no commands.

Rules for commands: the client keeps an ordered queue; each command gets `n = lastN + 1`; the server executes, in order, every command with `n > player.ack`, rejects invalid ones (still advancing `ack`), and reports `ack` in the private view. The client drops queued commands with `n <= ack`. Commands are never executed twice. Client state resets its sequence from the private view's `ack` on (re)connect.

**Optimistic prediction.** For `break`/`place` the client immediately applies the edit to a local overlay (`Map<cellIndex, {value, n}>`) and plays the effect; the overlay entry is removed once `ack >= n`, at which point the authoritative `edits` (same snapshot) already contain the accepted result. A rejected command therefore visually reverts on its own. Inventory clicks/crafts are predicted with the same pure functions from `src/shared/inventory.ts` / `recipes.ts` over a local copy, replaced by the private view once acked.

**Movement validation.** Server accepts `p` when `tpAck >= player.tp.n`, the AABB is not inside solid collision boxes (0.05 tolerance), and the horizontal displacement fits a movement budget that refills at 1.35× top speed and holds at most a 1.1 s lag burst (spent per move, never re-granted per update), falls stay within terminal velocity, and survival players never rise more than 1.6 blocks above where they last stood, swam, climbed or flew. Otherwise it issues a teleport `tp = { n: n+1, x,y,z }` back to the last valid position. Respawn, bed wake-up and `/`-free admin moves also use `tp`. Server-caused velocity (knockback, explosions) is sent as `imp = { n, vx, vy, vz }`; the client adds it once per new `n`. Fall damage is computed server-side from accepted positions (track the highest y since last on ground/in water/ladder; damage = floor(fall − 3)).

**Mining validation.** The server records when `mine` changes to a new target. A `break` is accepted if the target is within reach (4.5 survival / 5 creative from the eye, to the nearest point of the block), the block is breakable, and `elapsed >= breakTime(block, heldItem, onGround, inWater) * 0.6 − 0.15 s`, or the mode is creative (instant, but rate-limited to 5/s). `breakTime` lives in `src/shared/mining.ts` so the client's crack animation matches.

### What each screen is sent

The platform sends the public view to every socket and a private view to each playing seat, 20 times a second. Sending every entity to everyone grows with the square of the roster (351 KiB/s a phone at 64 before this design), so the public view carries almost nothing per frame and **each seat gets only what is near it, in its private view**. Entities travel as number tuples (`encodePlayer`/`decodePlayer` and friends in `shared/protocol.ts`); a decoded `Scene` holds the entity objects below, which is what the client code works with (`client/game/feed.ts`).

- **Interest** (`sim/views.ts`, distances across the ground): a seat is sent players within 96 blocks, mobs within 72 (ghasts 128; the dragon and its crystals 320, so the whole End sees them), items within 40, arrows within 72 and effects within 64 (explosions, crystals, portal openings and Nether cries 128; the dragon's death 320). The tuples of a tick are built once (`State.frame`) and filtered per seat.
- **Cadence** (`nearEvery`, `tvEvery`, `rosterEvery`): rooms of up to 16 get their scene in every snapshot; bigger rooms in every second one, seats taking turns, and the client draws further behind (`Entities` picks its interpolation delay from the feed interval). The display's feed comes every snapshot up to 8 players, every second up to 16 and every fourth above; it holds the nearest 24 players, 24 mobs, 12 items and 16 arrows round the followed seat, because every phone receives it too. The roster comes 5 times a second up to 10 players and twice a second above.
- **The followed seat** is chosen on the server (`pickFocus` in `sim/game.ts`): it moves on every 18 s, or at once when its player leaves or dies, to the next seat that has moved or swung in the last 6 s.
- **The edit journal** (`sim/journal.ts`): the platform diffs the whole cached `edits` list whenever `revision` changes (about 18 ms at 16,000 edits on the development machine, on every edit before this design). So an edit only joins `world.recent`, which every snapshot repeats as `recent`; the tail is folded into `edits` (and `revision` moves, sending one small patch) once it is 1.5 s old, or as long as `tailCap` (24 + a little per 2,048 journal cells) with at least half a second since the last fold, or 256 long. Clients show `edits` overlaid with `recent` overlaid with their optimistic overlay (`engine/edits.ts` applies only what changed).
- Caps: hostile mobs are counted round each player: `hostileCap` (2 + 6 × players within 64 blocks, at most 50; halved on easy, ×0.6 on day 0) against the monsters within 72 blocks, with a world total of 2 + 6 × players up to 144. Animals: 48 for ten players plus 4 for each further player (160 at most, what a save holds). Items ≤ 256 (merge nearby identical stacks), arrows ≤ 96, effects ≤ 256 (each lives 1.5 s).

## Gameplay rules (server owner)

- Survival: health 20, food 20, saturation 5, exhaustion from sprinting/jumping/mining/attacking. Food ≥ 18 regenerates 1 health / 4 s; food 0 starves to 1 health on easy, 0 on normal (peaceful regenerates and never drains). Fall damage, drowning (air 300 ticks, 2 damage/s at 0), cactus contact 1/0.5 s, zombie burning in daylight, creeper explosions (radius 3, block destruction except bedrock/obsidian, damage by distance, knockback), skeleton arrows, spider leap. Damage invulnerability 0.5 s; knockback via `imp`.
- Death: drop inventory unless `keepInventory`; death message; respawn command → bed spawn if valid, else world spawn; full health/food. Spawning, respawning and reconnecting give 5 s of protection (no damage, monsters ignore you), and hostile mobs within 16 blocks of the respawn point despawn.
- Mobs: zombie, skeleton, spider, creeper (hostile; spawn at night or in dark caves where sky/block light is low, at least 24 blocks from every player and out of their line of sight by day, never within 32 blocks of the world spawn on day 0, despawn beyond 96 blocks or randomly when far; peaceful removes hostiles). Cow, pig, sheep (shearable, regrows by grazing), chicken (lays eggs). Animals spawn with terrain in grassy biomes (deterministic per chunk when first loaded near players, bounded total), follow a player holding wheat/carrot/seeds, breed with food (baby grows in 5 min). AI: wander, flee when hit (animals), chase within 16 blocks with line-of-sight or recent aggro (hostiles), simple grid pathfinding (A* over walkable cells within 24 blocks, recomputed ≤ 2×/s) with jumping and water swimming, no mob-through-wall movement. Drops per MC.
- Item entities: dropped by mining/death/drop command; bob and spin; 0.5 s pickup delay for player-thrown items; magnet within 1.5 blocks; merge stacks; despawn after 10 minutes.
- Crafting: MC-style shaped and shapeless recipes (mirrorable) matched from the 2×2 grid (inventory) or 3×3 grid (crafting table screen). Recipe book command `craft` crafts directly from inventory ingredients (needs a nearby crafting table within 4 blocks for 3×3 recipes). Furnaces: input/fuel/output slots, 10 s per item, fuel times as MC, lit block state while burning; smelting continues when nobody is watching (tick loaded furnaces). Chests: 27 slots shared by everybody; breaking drops contents.
- Blocks: placement faces the player (furnace/chest/pumpkin/stairs/door/bed), logs orient by clicked face, slabs merge into double slabs, torches attach to walls, doors/beds place two blocks, hoe tills grass/dirt into farmland, seeds on farmland, bone meal advances crops/saplings, crops grow on random ticks (faster when watered), saplings grow into trees (same tree generator as worldgen via a shared function), water bucket places/picks up source blocks, sugar cane grows up to 3 tall. Placing may not intersect any player or mob AABB.
- Sleep: using a bed at night sets spawn and lays the player down (`wake`, Jump or Sneak gets up); when enough connected, alive players are sleeping (everyone in a group of up to three, half of a bigger one: `sleepNeed`), skip to morning (tick 0 of the next day). `View.sleeping` and `View.sleepNeed` feed the bed and TV hints. Survival toasts warn at dusk (tick 11500) and nightfall (13000, not in peaceful).
- Creative: instant break, no drops, infinite blocks (placing doesn't consume), flight (double-tap jump), no damage, creative palette command.
- Stats for results: per player mined, placed, crafted, mob kills, deaths, distance walked; world days survived.
- Outcome: `complete` only after the host finishes; winners = everyone (cooperative); rows show each player's highlights.

## Exploration, armor, villagers, the Nether and redstone (server owner unless noted)

Each system is one server module with hooks called from `game.ts`, `commands.ts`, `combat.ts`, `mobs.ts`, `views.ts`, `world.ts` and `save.ts`. The fixed tick order is: players → redstone → portals (Nether, End entry, End exit) → burning → fire blocks → spawners → the dragon (`ensureDragon`) → mobs (villagers, Nether mobs, primed TNT and the endgame mobs, through `CUSTOM_AI`; flyers move themselves) → fireballs → arrows (projectile kinds 2–5 route to their owners) → items → the void → furnaces → growth.

### Structures (`shared/structures/**`, `shared/loot.ts`, `sim/structures.ts`)

- Placement uses MC region grids (spacing / separation in chunks): village 32/8, desert temple 32/8, mineshaft 13/3; each start sits at a hashed chunk and is kept if its planner accepts the biome and terrain. Structures stay 24 blocks clear of the world rim and the Nether region, and temples never overlap villages. Dungeons are per-chunk features (about 1 chunk in 20) set beside cave floors.
- Each start is planned once per seed into paint operations bucketed by chunk and cached (64 plans per seed on a client, 20 per player on a server through `reserveStructurePlans`, for up to `SEED_CACHE` = 32 worlds, the most a room hub runs; with 64 a spread-out room planned the same villages again and again). `generateChunk` replays only its own bucket, so pieces join across chunk borders; every operation reads at most its own column, so the result never depends on load order. Painting costs about 0.03 ms per chunk; planning a village about 5–10 ms, once. Trees rooted inside a surface structure are removed whole, cacti inside are cleared, and nothing lava-lake-shaped lands inside.
- Villages (plains, forest, taiga, desert palettes): a well, 3-wide dirt-path streets (gravel over water), gabled houses and cottages, a large two-bed house, a blacksmith (furnace, village_smith chest), a library, 2–3 farms with water channels and ripe crops, and lamp posts. Buildings face their street on foundations filled down to the ground, with air cleared above. House doors are generated **open** because villagers walk only through open doors. `villagesNear(seed, cx, cz)` returns `{ center, houses: { bed, bounds }[], bounds }`: `center` is a standable path cell beside the well, `bed` is each bed's foot cell.
- Desert temples: a stepped sandstone pyramid with two towers and terracotta patterns; a hidden shaft drops to a sealed chamber with 4 desert_temple chests and the trap (a stone pressure plate on sandstone above a 3×3 of TNT).
- Mineshafts (y 8–60): corridors with plank floors over caves, fence posts and plank beams every 4 blocks, crossings, stairs, cobwebs, torches, chests in niches and rare spider spawners. Dungeons: a mossy cobblestone room with a zombie, skeleton or spider spawner and 1–2 chests (Blockwild's caves are narrow, so up to 12 floor and 3 ceiling holes are paved over).
- Loot is rolled once from the world seed and the chest's cell (`rollLoot(table, lootSeed(seed, index))`) the first time a generated chest is opened or broken; the roll clears the loot bits with an edit first (if the edit limit refuses, the chest stays sealed). Worldgen torches and lit furnaces count as light for monster spawning.
- Spawners register as their chunk generates. They wake for an unprotected player within 16 blocks, spawn 1–4 mobs on free floor within 4 blocks every 10–40 s (a cycle that spawns nothing retries a second later, like MC), hold off while 6+ of that mob are within 9 blocks, ignore the daylight and first-day rules, sleep in peaceful and are forgotten when broken. Only generated spawners run.

### Armor (`sim/armor.ts`)

Damage after armor = `damage × (1 − min(20, max(points / 5, points − damage / (2 + toughness / 4))) / 25)` (MC). Armor reduces mob, arrow, fireball, explosion, cactus, fire and lava damage, not fall, drowning, starvation or magma. Each reduced hit costs every worn piece `max(1, floor(damage / 4))` durability in survival; a worn-out piece breaks with a toast and chips. Explosions deal half of MC's `7 × 2·power` so point-blank blasts stay survivable for unarmored party players; armor cuts that further.

### Villagers and trading (`sim/villagers.ts`, `shared/trades.ts`)

- One villager (0.6 × 1.95, 20 health, persistent) spawns beside each house bed when its chunk is first populated; profession (0 farmer, 1 librarian, 2 armorer, 3 toolsmith, 4 cleric, 5 mason) comes from `professionAt(seed, village, bed)` and the seed hashes from the bed, capped at 64. Every village with 2+ houses gets exactly one mason, in the house picked from the village centre; the other beds keep the profession they had before masons existed.
- Routine, re-planned every ~0.5 s: stand still facing a player who has its trade screen open; flee monsters within 8 blocks (angry piglins only); panic after a hit; from tick 12000 to 23500 walk home and stand by the bed; otherwise stroll within 32 blocks of the village centre, preferring paths. Idle villagers look at players within 6 blocks. Zombies hunt villagers they can see within 16 blocks.
- `offersFor(profession, seed)` gives 3–5 deterministic offers with MC-like prices: buys first (every villager earns emeralds), then sells, then at most one rare diamond deal (40% of armorers and toolsmiths). Masons buy 10 clay balls, 20 stone or 12 quartz for an emerald and sell bricks ×10, chiseled stone bricks ×4, stone bricks ×8, terracotta, a quartz block or a quartz pillar for one; clerics may also buy 12 quartz. Uses: buys 16, sells 12 (some 16), rare deals 3; everything restocks at dawn. A trade runs on a copy of the inventory, so goods that would not fit change nothing.

### The Nether (`shared/nether.ts`, `sim/portals.ts`, `sim/fire.ts`, `sim/nether-mobs.ts`)

- Terrain comes from one 3D "solidness" field (floor and ceiling heights roughened by noise, large blobs for walls and floating islands, hourglass pillars), thickened near the walls. Open cells at y ≤ 31 are the lava sea. Soul sand valleys, gravel and soul sand shores, magma by the lava, quartz and gold veins, fire (only on netherrack), mushrooms, hanging glowstone and lava "eyes" follow. Same cross-engine math rules as worldgen.
- Portals: an obsidian frame with a 2–21 wide × 3–21 tall interior (either plane, corners optional) lights with flint and steel or fire. Standing in it for 4 s (1 s in creative) travels 8:1 (overworld (x, z) → (3584 + ⌊x/8⌋, ⌊z/8⌋) clamped to [x0 + 8, x0 + 503] × [8, 503]; back → (8·(x − 3584), 8·z) clamped to [16, 4079], nudged out of the Nether's own corner and out of the End's, so a Nether portal never leads into the End; nether portal cells inside the End carry nobody). Arrivals reuse a portal within 128 blocks (overworld) or 16 (Nether), else build a 4 × 5 portal on firm dry ground with room on both sides within 16 blocks (closest to the player's height in the Nether, the surface in the overworld), else carve one in place on an obsidian platform. The player stands in the arrival portal facing its roomier side (`tp.yaw`) and cannot re-enter until stepping out. Breaking any frame or portal cell unlights the whole portal; the portal index rebuilds from edits on load. Items and mobs don't travel.
- Fire and burning: fire never spreads and burns out after 2–6 s unless on netherrack or magma; fire touching TNT primes it. Players and mobs burn on one timer at 1 damage/s: lava 15 s (plus 4 damage per 0.5 s while inside), fire blocks 8 s, fireballs 5 s, zombies and skeletons in daylight 8 s (so they keep burning briefly in shade). Water puts it out (`fizz`). Creative players, piglins, ghasts, blazes and objects (primed TNT, end crystals) never burn. Monsters don't spawn in or path through lava.
- In the Nether, beds explode (power 5) and water cannot be placed (it fizzes and the bucket empties).
- Mobs spawn only inside the region, never within 24 blocks of a player: zombified piglins in groups of 2–4 on the floor (cap 4 + 4 per player there, max 20; neutral, and hitting one angers every piglin within 24 blocks for 30 s; they hit for 5), ghasts in 5×5×5 air pockets (cap 1 + 1 per player, max 4) that lock onto a visible player within 48 blocks, cry for 1 s and fire. Fireballs fly straight at 14 m/s, hit for 6 plus 5 s of burning, then make a power-1 explosion that lights about a third of the open floor. Hitting a fireball (the crosshair targets it; `attack` with its id within reach + 1.5) sends it back along your look, and a returned fireball kills a ghast outright.

### Redstone (`shared/redstone.ts`, `sim/redstone.ts`)

Server-simulated; the client only renders states and uses the shared `wireShape` for dust meshes. Semantics follow MC closely enough that tutorials work:
- A redstone tick is 2 game ticks. Sources: lever, button, pressure plate, lit torch, redstone block (15). Levers and buttons strongly power their support, plates the block below, a lit torch the block above (its other sides power components only, never blocks, and never its own support), a repeater the block in front.
- Conductors are opaque full blocks except pistons and redstone blocks. Dust powers the block beneath and the block it points into weakly; weak power reaches lamps, doors, pistons and TNT but not dust. A lone dot powers all four sides, a single join runs straight through; dust steps up and down unless a conductor cuts the step. A dust network (≤ 8192 cells) is rebuilt at once, so lines turn off instantly.
- Timings: torches 1 redstone tick, repeaters 1–4 (short pulses extended), lamps 2 to go dark, buttons 1 s (stone) / 1.5 s (oak), plates release 1 s after the last touch. A torch that toggles more than 8 times in 60 game ticks (checked on turn-off) burns out for 3 s.
- Plates sense bodies each tick in the inner 14/16 of the footprint, 0.25 tall (stone: players and mobs; oak: also items and primed TNT), so generated plates like the temple trap need no registration. Doors follow power only when it switches, so oak doors still open by hand.
- Pistons push up to 12 blocks (failing on bedrock, obsidian, chests, furnaces, spawners, portals, extended pistons, unloaded chunks and the world edge), break the first fragile block in the way with drops, move blocks with their state, pause 2 ticks after each move and shove players (by teleport), mobs and items one block. Sticky pistons pull one block back. Breaking the head breaks the base and vice versa. The client slides moved blocks from the `piston` fx.
- TNT primes into a `tnt` mob (80-tick fuse; a = fuse / 4 for the flash) that pops up, falls and explodes at power 4, chain-priming nearby TNT with a short random fuse.
- Observers watch the cell in front: any change of id or state there (placing, breaking, crops growing, lamps, pistons, edits restored on load) turns them on 2 game ticks later for 2, strongly powering the block behind (they don't conduct; dust joins only their back). Two facing each other make a 4-tick clock; one moved by a piston arrives off and pulses once. At most 256 observer switch-ons run per tick (the rest wait a tick) and at most one 'observer' fx is added per tick. The tick runner takes every job due this tick off the queue before running any, so a job can re-queue itself.
- Daylight detectors show `round(15 × max(0, sin(2π·time/24000)))` with nothing solid above (sky is all-or-nothing: no sky-light map on the server), 15 minus that when inverted, and 0 in the Nether and the End in both modes; they re-read once a second and at once when placed or toggled.
- Everything runs only in loaded chunks and nothing is saved: loaded edits are marked dirty, so lamps stay lit, pressed buttons release and clocks resume. Budget ≤ 1 ms per tick (a 52-dust clock plus a 12-piston door measures about 0.03 ms mean; 400 observer clocks about 1.3 ms).

## The endgame (server owner unless noted)

The route a party follows: Nether fortress → blaze rods → endermen for ender pearls → eyes of ender → stronghold → open the End portal → the End → destroy the crystals → defeat the Ender Dragon. Every step must be findable, fair, readable on a phone and fun with 1–10 players, and nothing may soft-lock (a dragon stuck under the island, a crystal out of reach, an arrival in the void).

New mobs (appended to `MOB_TYPES`; old indices never change): 12 blaze (monster, 0.6 × 1.8, 20), 13 enderman (neutral monster, 0.6 × 2.9, 40), 14 ender_dragon (boss, 200), 15 end_crystal (object, 2 × 2 × 2, 1), 16 silverfish (monster, 0.4 × 0.3, 8). `mobBoxes(mob)` in `protocol.ts` returns every hit box: one for normal mobs, the dragon's eight `DRAGON_PARTS` (head, neck, body, two wings, three tail segments) posed from its yaw, `pt` and a body centred 2 blocks above its position. Client targeting and server attacks and arrows test all of them; the head takes ×1.5 (the `attack` command carries `part`, re-checked by the server).

### Nether fortresses and blazes (`shared/structures/fortress.ts`, `shared/loot/fortress.ts`, `sim/blaze.ts`)

- `fortressesOf(seed)` gives 3–4 fortresses inside the Nether walls, at least 64 blocks apart; the first is always 24–60 blocks from `netherSpawnPoint(seed)`, where a portal built at world spawn leads. Each is `{ center, bounds, spawners }` (the hub at deck feet height, inclusive bounds down to the pier feet, 1–2 blaze spawner cells). The deck height (44–56) is the most open air among 9 sampled Nether chunks, so early fortresses never end up buried.
- A fortress is a 7 × 7 crossroads hub with four arms in a seeded order: a **spawner arm** (a 5-wide bridge on stepped arches with piers into the lava sea, a short stair and a raised, fence-railed 9 × 9 platform round a blaze spawner), a **castle arm** (fence-windowed corridors, a corridor crossing, a loot room with 1–2 `nether_fortress` chests, a nether wart garden on raised soul sand beds edged with stairs, and an 11-high stair tower with a railed lookout roof, the landmark seen from afar), a **crossroads arm** (a second crossroads with crumbling side bridges, then a second spawner platform half the time or a bridge that crumbles away) and a **long arm** (a long crumbling bridge). Bridges and rooms clear their own space, so they tunnel through netherrack. The plan is made once per seed and baked into per-chunk buckets; nether brick fence joins come from the plan, so a fence never joins natural netherrack. About 1.2 ms per Nether chunk inside a fortress; planning costs 30–110 ms once per seed.
- Loot: 2–5 stacks per chest. Gold, iron and nether wart are common; obsidian and flint and steel give a way home; diamonds, golden apples and gold or iron armour pieces are rare.
- Blazes hover 0.6–1.8 blocks over the floor, bob, sink slowly and hold their height over drops, drifting while idle. They lock onto a visible player within 32 blocks, rise just above the player's head and close to about 10 blocks; they glow for 1 s (`a = 3`), fire a volley of 3 small fireballs 0.3 s apart (`k: 2`, 15 m/s, 5 s life, 5 damage plus burning; on the ground they light a fire but never break blocks; scattered wider up close so they can be dodged) and cool down 4–6 s. A blaze that has just spotted someone waits 1.5 s before its first volley. Up close they burn on touch (6 plus burning). Fire-immune. A player kill drops 1 blaze rod (a 1/3 chance of a second).
- Fortress spawning runs only while a player is inside a fortress's bounds: mobs appear on nether brick floors 24–48 blocks away at light ≤ 11, two in three blazes and the rest zombified piglins; blazes cap at 3 + 2 per player in the Nether (max 10).

### Endermen and ender pearls (`sim/enderman.ts`, `sim/pearls.ts`)

- Endermen are neutral until provoked: a survival, unprotected player staring at the **head** box (the top 0.55 of the body) within 64 blocks with nothing opaque between (glass doesn't block it) for 0.5 s, or a hit. Then they scream, stare back for 1 s (`a = 3`, `MS.ANGRY` while hunting) and hunt, teleporting to 2–5 blocks from a far, hidden or unreachable target; they hit for 7.
- They teleport (up to 32 blocks, always onto a safe floor) when hurt: arrows are always dodged (no damage), water deals 1 every 0.5 s and teleports them without angering them, other damage always teleports, and a player's punch a third of the time.
- Spawning (checked once a second, 24–48 blocks from players, never within 24): overworld nights only at light ≤ 7, rare, cap 1 + players/2, leaving at dawn when nobody is within 32 blocks; the Nether rarely, only on soul sand above the lava-sea shore; the End commonly, on end stone, cap 16.
- Drops: 1–3 ender pearls on every player kill (`pearlPity` is still saved but no longer used).
- Ender pearls (`useItem`): a `k: 5` projectile at 30 blocks/s along the view (from the eye + 0.4·dir, 0.1 lower), gravity 12 b/s², drag 0.99 per 20 Hz tick, 1 s cooldown per player, one spent in survival. It lands on the first solid block or mob: the thrower teleports to a standing spot there (nobody moves if no spot fits), with 'teleport' fx at both ends and 'pearl' at the landing, and takes 5 fall damage (no armor, protection still applies). Pearls vanish below the void line, after 20 s or when the thrower leaves. They pass through other players.

### Strongholds, eyes of ender and silverfish (`shared/structures/stronghold.ts`, `shared/loot/stronghold.ts`, `sim/ender-eyes.ts`, `sim/silverfish.ts`)

- `strongholdSites(seed)` places three strongholds 640–1152 blocks from spawn about 120° apart (exact rotation constants, no trig), more than 300 blocks from the Nether and End corners, with the portal room floor at y 16–40 and 16 blocks of rock above. A site under the sea or a river re-rolls its jitter and distance (up to 64 tries, the later ones turning up to ±28°) and keeps the driest, so rooms sit under land (at worst a shallow shore). `strongholdsOf(seed)` gives the portal room centres; each site also has a `landing` (a safe floor cell just inside the room's door).
- `planStronghold(seed, index)` grows a maze from the portal room's single door, piece by piece: corridors, stairs up and down, turns, crossings, a prison hall (barred cells with door-buttonless iron doors), a fountain room (a static water source on a chiseled pillar over a basin, since water doesn't flow), one or two two-storey libraries (bookshelves, ladders, cobwebs, `stronghold_library` chests: paper, books, a rare pearl) and two or three store rooms (`stronghold_corridor` chests: pearls, iron, bread, apples, redstone, gold, iron tools and armor bits, a rare diamond or golden apple). Doors are 3 × 3 arches, oak doors, iron grates or iron doors with a stone button on each side (a button powers the wall block beside the door). An attempt missing a required room retries with a new seed, up to 12 times. Walls stay where caves cut through. About 30 ms per stronghold, only when a chunk near one generates.
- The portal room: stairs up to a platform with 12 inward-facing `end_portal_frame`s round a 3 × 3 opening over lava, the silverfish spawner on the landing, iron-bar windows and wall torches (placed so the spawner stays dark enough). Each frame starts with an eye 75% of the time (about 9 of 12, so a few eyes finish it), never all 12. Iron bars join only cells in the plan.
- An eye of ender (`useItem` while not aiming at a frame) is a `k: 3` projectile: it rises and glides up to 12 blocks towards the nearest stronghold's landing (stopping short of walls and ceilings; within 12 blocks of the room it stops right above the landing, so digging straight down lands on the room's floor, never in the lava), hovers about a second, then drops as an item (80%) or shatters (20%, 'shatter'). One eye in flight per player. In the Nether or the End it just drifts down and drops, with a toast. Survival spends the eye.
- Using an eye on an empty frame inserts it ('eye'). When all 12 frames of a ring hold eyes and face inward (whichever is filled last, whatever the room's rotation), the 3 × 3 fills with end_portal once ('portalOpen', a toast for everyone within 64 blocks). Frames are unbreakable in survival; creative can break them (an open portal stays open, like MC).
- Touching the lower 12/16 of an end_portal cell outside the End calls `arriveInEnd`.
- Silverfish chase a visible player within 12 blocks (keeping up to 24) and bite for 1 each second. Breaking silverfish stone releases one that targets the nearest player (none in peaceful); a hurt silverfish breaks the nearest silverfish stone within ±6 sideways and ±3 up and down into more, never past 8 within 8 blocks. The portal-room spawner is an ordinary spawner (see Structures).

### The End (`shared/end.ts`, `sim/end.ts`)

- `generateEndChunk(seed, cx, cz)`: one end stone island centred on (3840, 3840), its radius wandering about 90–123 blocks (noise erodes the outline; an eastern bulge carries the arrival cave), a gentle dome from y 63 at the fountain to about 57 at the edge, and a rounded underside hanging to about y 2 over the void. Ten obsidian pillars stand on a ring of radius 42 (`PILLAR_RING`); `endPillars(seed)` gives them in ring order (the save's crystal indices) with radius 2 + ⌊k/3⌋ and a bedrock cap at y 76 + 3k for seeded rank k; ranks 0 and 1 (the shortest) get roofed iron-bar cages. `crystalSpot(pillar)` is the crystal's feet on the cap. At the centre the exit fountain is bedrock: a 20-cell bowl (`EXIT_PORTAL`, floor y 63, portal cells at `EXIT_Y` = 64), a rim with rounded corners, a 4-tall pillar (y 64–67) topped at `PERCH_Y` = 68 (where the dragon perches and the egg sits) and four wall torches. The arrival platform (5 × 5 obsidian at y 48 with 3 air above, `END_ARRIVAL`) sits in a small cave inside the island with a 3-wide stairway climbing west to the surface, so it is never over the void. About 0.2 ms per chunk, engine-exact math only.
- The void: a player below y = −64 (`VOID_Y`) takes 4 damage every 0.5 s ('fell out of the world', ignoring armor and protection; creative is immune). Mobs (never the dragon), items and projectiles down there are removed.
- `arriveInEnd` rebuilds the platform as edits, places the player on it facing the island (west), gives 3 s of protection and a toast. Inside the End, touching an end portal (`tickExitPortal`) sends the player to their bed or the world spawn ("Returning home…"). Until the dragon dies the only way home is dying (respawn with the usual keepInventory rules).
- Rules: beds explode in the End (like the Nether); only endermen spawn there; water works normally.

### The dragon (`sim/dragon.ts`)

- One dragon per world, spawned above the island centre the first time a player is in the End (`ensureDragon` also puts a crystal on every pillar listed in the save), health 200. It thinks wherever it is (over unloaded chunks too) and never despawns.
- Flight steers with a limited turn rate, so paths are smooth arcs, clamped to a cylinder of radius 150 and y 68–118 (never under the island). Phase 0 circles the ring lazily (radius 54–78, y 72–96). Every 10–25 s (6–14 s once the crystals are gone) it strafes (1) a random survival player in the End: it dives to 12 blocks above them and spits a dragon fireball (`k: 4`; a pair 2 blocks either side once the crystals are gone) once it sees them, or blind after 5 s of diving so cover only softens it. Every 40–70 s (half that once the crystals are gone) it spirals down (2) onto the fountain pillar and perches (3) for 6–10 s with its head lowered (`pt` −0.35, within sword reach from the ground), breathing acid at the nearest player every 1.8 s; its landing gust (no damage) pushes players within 9 blocks of the fountain out from under its body to where the head is in front of them; taking off (4) early after 50 damage on one perch. Players inside its body or wings take 5 damage and are knocked away (wing buffet).
- Healing: the nearest crystal within 32 blocks heals it 1 per 0.5 s and shows its beam through `a = 3`; breaking that crystal deals 10 to the dragon. Crystals break from any damage with a power-6 blast that breaks no blocks and chains to nearby crystals; its damage is tuned to about 13 point blank and 10 at melee reach (before armor) so breaking one by hand is survivable, while the knockback and 12-block reach match MC. Caged crystals need the bars broken or an arrow through the gaps.
- Damage: only players hurt it (not explosions, fire or its own acid), with the usual 0.5 s invulnerability and ×1.5 on the head; nothing hurts it while dying. Dragon fireballs burst into acid clouds (radius 3, 3 s, 3 damage per second, armor applies, no block damage; 'acid' fx).
- Death (phase 5, 'dragonDeath'): 8 s of rising with light beams and a growing glow, then `dragonSlain`: the exit portal fills the bowl, the egg appears on the pillar (first time only), `stats.dragons` counts it, `victory` is recorded once (names of players who hit it in its last 60 s, or everyone in the End), a 'portalOpen' fx plays and everyone gets a toast. A world saved mid-death finishes the death on load.
- The boss view `{ name, health, max, crystals }` is published while the dragon lives (or dies, reading 0) and someone is in the End. Health and remaining crystals sync into the saved End state every tick; the position is not saved (it resumes circling).
- Respawning: four end crystals on the middle of each side of the open portal's rim (`EXIT_RIM_SIDES`) bring it back: the portal closes, the pillar tops are restored to their generated cells, every pillar gets a fresh crystal, and the first victory and the egg stay as they were.
- Balance: a scripted solo fight on normal (diamond sword, iron armor, a bow, cobblestone to pillar) clears every crystal and kills the dragon with 28 arrows without dropping below 16 health; real players with imperfect aim take longer.

### Goals, the boss bar and the victory celebration (UI owner)

Soft side goals add Build with quartz and Build an observer clock. After victory the chip turns purple: "You beat Blockwild! Keep building.", then "Next idea: …" for any open side goal; it stays dismissible.
- Boss bar (`endgame.tsx`, `BossBar`): a purple MC-style notched meter with the dragon's name, health and a crystals line, shown to players whose private view is in the End and on the TV while its spectator camera follows someone in the End (`hud.focus`).
- Celebration (`Celebration`, `useCelebration`): the first time a world's `victory` appears on a device (remembered in `blockwild.victories`, last 20 worlds), every player screen and the TV show a pixel dragon silhouette, "The Ender Dragon has been defeated!", the final blows, the day, a credits-style scrolling journal of world totals and each player's awards (from `view.journal`) and drifting pixel sparks, with a 44 px **Continue**. It is not modal (the host's Room menu opens over it), releases the mouse on desktop without opening the pause menu, is reduced-motion safe (no sparks, a plain scroll box), and closes itself on the TV after 45 s.
- The results screen shows "Ender Dragon defeated on day N by …" and the **Dragon slayer** award for everyone in `victory.by`. TV cards carry `data-dim="overworld|nether|end"` and show "In the End" in purple. The creative palette and recipe book gain "The End" tab (end stone family, purpur, frame, egg, pearl, eye, crystal); the quartz set sits under Building and the observer and daylight detector under Redstone. One-line hints cover the eye of ender, ender pearl, end crystal, observer and daylight detector.

## Saves (server owner)

Format version 11 for survival and creative worlds (versions 9 and 10 still load) and version 13 for Caper City worlds (version 12 still loads; see that section: the same record plus city settings and one `c` array per player, no animals or villagers). **v11** is the same record in a smaller hand: `edits` is base64 of the packed, deflated journal (`sim/journal.ts`: sorted cell indices as delta varints, then 16-bit values); every slot list (`inv`, `armor`, chest and furnace `slots`) is base64 of 6-byte records (slot, item id, count, damage); `populated` is a deflated bitset; up to 96 players (a full room and half as many again who played earlier), 160 animals and names of at most 16 characters (the room's limit). The worst legal save (the fullest journal the byte budget allows, 96 full inventories with three-byte names, 64 full chests) is 248 KiB and a test builds it. The paragraphs below describe the fields, which v11 did not change (v10 adds `end`, `victory`, `stats.dragons`, the pearl pity counter and the mason villager `p = 5`; worldgen outside the new structures is byte-identical to v9, guarded by golden chunk hashes, so old worlds keep every edit and gain strongholds, fortresses and the End only in untouched cells; v9 edits, beds, animals, villagers and players inside the End corner are dropped). Versions 1–8 are refused with the old-save message: edits are differences from generated terrain, so a version 8 world would silently change under the expansion generator). `{ format:'blockwild', version:10, seed, worldId, mode, difficulty, keepInventory, time, day, edits: base64 of packed little-endian (uint32 cellIndex, uint16 value) entries, players:[{ name, x,y,z, yaw, pitch, health, food, saturation, inv (compact), spawn }], chests:[{ i, slots }], furnaces:[{ i, slots, burn, burnMax, cook }], animals:[{ t, x,y,z, s }], stats }`. Players match by exact unique name on load; unmatched players spawn fresh. Validate everything; `loadSave` never mutates live state. `tests/save.test.ts` builds the worst legal save and asserts < 256 KiB, loads a real version 10 save (`tests/fixtures/v10-save.json`) and checks that the journal limit follows the packed size. Version 9 adds `armor` per player and `villagers: [{ x, y, z, p, home?, uses, seed }]` (≤ 64; offers derive from profession and seed, so only uses are stored). Chest and furnace records may sit on unedited cells (generated village chests and furnaces); `createState` drops any whose terrain no longer holds that block. Generated containers gain state only when first opened, and past the caps (64 chests, 32 furnaces) they stay shut with a toast, so a save always loads. Redstone, portal and fire indexes are not saved: they rebuild from the loaded edits.

## Big rooms and where the limits are

The manifest seats the room's ceiling of 64; 32 is the size the game is tuned and measured for (README, "Big rooms", has the figures). What was sized for ten and how it scales now:

- Traffic: per-seat scenes, the capped TV feed, the slim roster and the bag on demand (see "What each screen is sent"). One dense crowd still costs each of its phones about 45 bytes a player and 40 a mob per scene.
- Server memory and terrain: the chunk cache holds `max(640, players × 56 + 128)` chunks of 64 KiB (`chunkCapacity` in `sim/game.ts`); each connected player keeps a 7 × 7 block of chunks loaded (`LOAD_RADIUS` 3). `streamChunks` generates ring by ring across all players (everybody's own chunk before anybody's far ring) within 2 ms a tick, at least one chunk a tick; terrain a player stands on is generated on demand if the budget has not reached it. Many players travelling fast in different directions is what overruns a tick first.
- Mobs: every mob scans all players for the nearest each tick and `separate` compares simulated mobs pairwise (fine for the few hundred the caps allow); pathfinding shares 1,500 A* nodes a tick (`PATH_BUDGET`), 300 a plan, so about five full plans a tick. Mobs further than 80 blocks from every player, or in chunks that are not loaded, do not think.
- Movement: a player's own position is client-authoritative inside an envelope sized for walking and creative flight (`walkBudget` in `sim/players.ts`: 1.35 × 5.6 or 10.9 m/s). Anything faster needs its own envelope.
- The client streams terrain through one worker (three columns in flight) at view distances of 4, 6 or 8 chunks.
- Modes: `Settings.mode` (`'survival' | 'creative' | 'city'`, `MODES` in `shared/protocol.ts`) is read directly where rules differ (`sim/commands.ts`, `sim/players.ts`, `sim/mobs.ts` `huntable`, `shared/physics.ts` `stepBody`, `REACH`, the HUD and controls); the server's rule checks treat everything but creative as survival rules, and the city adds its own through `State.city` (null in the wild). Terrain comes from `generateChunk(seed, cx, cz, terrain)`: `'wild'` picks a generator by region (the Nether and End corners), `'city'` is Caper City. `terrainOf(mode)` gives it to the server (`createState`), the client worker (`init` message) and the scene's world cache key.

## Client architecture

- `src/client.tsx`: the `GameClientModule`. `SceneView` lazy-loads `src/client/scene.tsx`. `DisplayView` (watching host, TV), `ControllerView` (every playing seat, including a playing host; no separate PersonalView needed) render HTML HUD/menus layered above the scene canvas.
- SceneView and ControllerView are mounted separately by the shell; they communicate through a tiny module-level store `src/client/store.ts` (subscribe/get/set, no React dependency in the store itself) holding: local predicted player state (body, health), selected slot, targeted block/mob, open screen, pointer-lock state, touch control state, predicted inventory, pending command queue, settings like render distance and sensitivity. **The command queue and the single `setInput` call live in the scene's game loop** so exactly one component sends input.
- Rendering (engine owner) runs in `src/client/engine/`: a Web Worker (`worker.ts`, loaded with `new Worker(new URL('./worker.ts', import.meta.url), { type:'module' })`) generates chunks with the shared worldgen, applies edits, computes sky light and block light (BFS flood fill, 0–15, across chunk borders), and builds meshes per 16×16×16 section with face culling, per-vertex ambient occlusion and smooth lighting. It returns transferable typed arrays (positions, uvs/texture layer, normals or face ids, AO+sky+block light) and a copy of the chunk cells for the main thread (physics/raycast). Separate opaque, cutout (leaves/plants/glass) and translucent (water/ice) meshes; translucent sorted per section by distance. A custom shader applies a texture array (or padded atlas) with nearest filtering and mipmaps, smooth light as `max(sky * daylight, block * warmTorchColor)` with a gamma curve, AO, distance fog blended to the sky colour, underwater tint, gentle leaf/plant sway, animated water. Sky dome shader with sunrise/sunset gradient, sun and moon, stars, drifting blocky cloud layer at y≈140. Render distance presets: low 4 chunks, balanced 6, high 8 (default: balanced on desktop, low on coarse-pointer devices), with fog at the edge. Chunk load order spirals from the player and prioritizes the view frustum; budget worker results per frame (≤ 4 ms upload) to avoid hitches. Target 60 fps on a mid-range phone at low.
- Engine public API (`src/client/engine/index.ts`):
  ```ts
  class VoxelEngine {
    constructor(opts:{ scene:THREE.Scene; seed:number; atlas:BlockAtlas; renderDistance:number; scope:ResourceScope; onError(e:unknown):void });
    readonly world: ClientWorld;              // main-thread cells for physics/raycast: getCell(x,y,z), isLoaded(x,z)
    setEdits(edits:[number,number][], recent:number[], overlay:ReadonlyMap<number,number>): void;   // journal + server tail + optimistic overlay (engine/edits.ts keeps the layers and reports only changed cells)
    update(camera:THREE.PerspectiveCamera, dt:number): void;   // streaming, uploads, sorting, animation uniforms
    setTime(dayTicks:number, day?:number): void;   // sky, sun, light uniforms; the day turns the moon's phase
    lightAt(x:number,y:number,z:number): number;   // 0–1 combined light for entity tinting
    setRenderDistance(chunks:number): void;
    setUnderwater(on:boolean): void;
    ready(): Promise<void>;                   // resolves when chunks around the spawn are meshed
    dispose(): void;
  }
  ```
  Plus `BlockOutline` (selection box from `selectionBoxes`), `CrackOverlay` (10 stages), `SkyRenderer` inside the engine.
  Look (2026-11 pass): sky light is split in two (`skyState` gives `fill`, `direct` and the `light` direction): every sky-lit face gets the fill and faces turned to the sun (the moon at night) get the direct part on top, warm and long when the sun is low, so the land reads differently at every hour; the face direction comes from screen derivatives, crossed plants count as facing up, and the End's flat light has no direct part. Torch light flickers a few percent. A thin haze builds over the whole view distance before the edge fog. The sky has a round sun with slow rays, a pixel moon with eight phases (full on a new world's first night) and clouds lit warm from below at dusk. `lightDirection` and `night` expose the light for entity shading and night-only effects.
  Expansion members: `shared` (atlas uniforms, including the current lava, portal and fire animation layers), `inNether` (the Nether look follows the camera: no sky, sun, moon, stars or clouds; dense dark-red fog `#2a0b08` → `#4a1410`; a warm ambient floor; 0.6 s fade; the TV switches with its subject), `setGlows(data, count)` (up to 4 point lights for fireballs and TNT) and `slide(x, y, z, cell, dx, dy, dz, seconds, veil)` (piston animation; the destination is hidden from the meshes only). The mesher has a shape for every block (fence posts and bars, dust from `wireShape` tinted by power, lever handles, repeater torches by delay, piston base/rod/head, thin portal slabs, MC's crossed fire planes, the two-sided spawner cage, lava as a self-lit 14/16 surface).
- Art (art owner): `src/client/art/atlas.ts` paints every block face texture as 16×16 pixel art into canvases at runtime (deterministic, hand-designed palettes, no external images), builds the texture array/atlas, the 10 crack stages, water/lava-free animated water frames, and `itemIcon(id): string` (data URL) for UI: isometric mini cubes for blocks, flat 16×16 sprites for items (tools, food, ingots, etc.), cached. ## Caper City: the third mode (`mode: 'city'`)

A cartoon open-world city sandbox inside Blockwild: 1–64 players land in a pre-built voxel city full of residents with jobs and routines, borrow or buy vehicles, run gigs for coins, make mischief and get chased by the Watch. The tone is slapstick: bonks, tumbles, cream pies and knock-outs with stars, never gore or killing; nothing adult. Everything in it (name, map, characters, vehicles, items, signs, UI) is original to this game: no existing game or its wiki was used as a specification, and it does not build on the pieces of Blockwild that follow Minecraft (creatures, the Nether and End, villager trades, the default player look). Survival and creative are untouched: `State.city` is null there and every city rule hangs off it.

### What the owner asked, answered

- **Earn**: gigs from job boards (parcel rounds from the Zip Post depot and the town hall, hot food runs from diners and the market, cab fares from cab stands), coins that pop out of bonked residents, the swag bag in a grabbed till (sold at a pawn shop), a vehicle sold at the scrapyard. **Spend**: food (mends hearts), gadgets (cream pies, a disguise kit), building blocks, vehicles from the dealer and the airfield (yours for good: no heat for driving them, and they come when called from the map), a flat (heat drains four times as fast near it) and a plot of land to build on; fines, clinic bills and paying heat off at the Watch House. Numbers live in `shared/city/economy.ts`.
- **Consequences** (the second helping below adds the lock-up, bounties and more): mischief that a resident or officer *sees* raises **Heat** (0–100, a filling bar with named tiers: Noticed 10, Wanted 35, Hot 60, Red Alert 85; an officer's eyes count half as much again; unwitnessed mischief is free). The Watch answers by tier: at Noticed one officer walks over and writes a 15-coin ticket; from Wanted officers run (faster each tier) and reinforcements arrive from round a corner; at Hot a cruiser, at Red Alert two. An officer within reach of a player on foot or nearly stopped for 1.2 s makes the arrest: a fine of 10 % of the coins carried plus 25 per tier, the loss of carried loot and a walk from the Watch House steps. Heat drains (3 a second) once no officer has seen the player for 8 s. Knocked out (health 0) means waking at the Patch-Up Clinic with a bill (30 coins + 5 %). There is no hunger in the city and nothing is ever lost from the pockets but loot.
- **Round end**: free play ends when the host finishes it (as in the other modes); the host may instead set a round of 10, 20 or 30 minutes, after which the round finishes itself (`outcome.complete`, which the room server polls). Results are the **City Ledger**: everyone ranked by net worth (coins + what they own), each with awards (Tycoon, Most Wanted, Slippery, Road Hog, Bonk Champion, Jailbird, Sky High, Model Citizen: `cityAwards`). Every award has a least amount that earns it; Tycoon needs more than the 40 coins everyone starts with, so a round nobody did anything in hands out nothing.
- **The TV (up to 64)**: the spectator camera goes to the player with the most heat (else the usual busiest seat); a city map with every player as a dot (names up to 12 players, a red ring round the wanted), the three most wanted, the five richest and a ticker of the last three news lines (arrests, escapes, purchases, big gigs).
- **Saves**: city worlds are written as format 13 (12, the first city format, still loads and starts the newer things from scratch); survival and creative worlds are still written as 11, byte for byte. The city, its residents, parked vehicles, traffic and everything in `shared/city/extras.ts` derive from the seed and are never saved; nothing is saved for the world at all. A city save adds the two city settings and one array of 28 integers per player (`CITY_FIELDS`: coins, owned vehicles, flat, plot, nine career totals as in version 12, then two halves of passport stamps, two of golden feathers, errand steps, standing, look, businesses and seven more totals, each with a bound the parser enforces) and reuses the edit journal for what was built on plots; it must hold no animals or villagers (the parser refuses them), which is more room than the records take: the worst legal city save is 246.3 KiB of the 256 allowed (a test builds it; it was 237.4 before the second helping).
- **Editing blocks**: the city itself cannot be broken or built on (the client does not even start mining it). A player who buys a plot (12 × 12 × 24, twelve in the city) may place and break blocks inside it, with blocks from the hardware shop. Those edits are ordinary journal entries, so the building limit, the byte budget and the save size are exactly as before. Crafting is off in the city.

### World (`shared/city/plan.ts`, `gen.ts`, `buildings.ts`)

- The city is a deterministic function of the seed, 656 × 656 blocks at `CITY = { x0: 1728, z0: 1728 }`, flat at `GROUND = 64` (feet), on an island in a shallow sea, with a boardwalk, beach and pier to the south and Gullwing Field (runway, hangars, helipads) on a strip to the east. Players and vehicles are kept inside `CITY_BOUNDS` (the island plus about 100 blocks of water, ceiling y 122) by `stepRide` and by the server's move check, so the Nether and End corners of the world storage are unreachable.
- Layout: a 10 × 10 grid of 48-block city blocks separated by 16-block road corridors, so every corridor is exactly one chunk wide (sidewalk 3, parking strip 2, two 3-block lanes, parking 2, sidewalk 3; right-hand traffic) and every block is 3 × 3 chunks. The zoning map (`ZONES`) is fixed, so the city can be learned and its map reads the same on every screen; the seed varies how office and flat blocks are divided, heights, materials, shop names, residents, parked cars and park details. Districts: Brasswick (office towers, the bank, the town hall plaza where everyone starts, the hotel, the clinic, the Watch House), Pennymarket (rows of shops, the market square, the cinema), Quillside (flats), Larkrise (houses, the school and the buildable plots), Cinder Yards (warehouses, the depot, the scrapyard, the dealer), Sunny Strand (the funfair and the south shore), Mossback Park and Gullwing Field.
- A lot is a few numbers (`Lot`: bounds, the side its front is on, kind, floors, a style hash). `generateCityChunk` fills the ground, paints its street or its block's lots through a `Canvas` that clips every box to the chunk before looping, so no plan buckets are kept and nothing depends on generation order (a test generates chunks in two orders and compares). Measured: 0.8–1.2 ms a chunk median on the loaded development machine (the wild: about 6), and about 1,000 visible quads a column against the wild's 3,400.
- Painters draw in the lot's own frame (u along the front, v inward, y above the street). `building()` is one parametric block (walls, trim, windows on every storey, parapet and roof clutter or a gable, a doorway, and behind it an 11-deep room with ceiling lights, a counter, a till and shelves); each kind is a preset of it plus its own props. Upper floors are solid behind their facades; ground floors of shops, lobbies and halls are real rooms; shops and flats have a fire-escape ladder to the roof. `footprint(lot)` and `layoutOf(lot)` give the plan the same doorway, counter, till and job-board cells the painters use.
- New blocks 146–171 (own textures in `client/art/city.ts`). Several are families whose state picks the look (`BlockDef.variants`): asphalt (plain, centre lines, crossings, bay ticks), pavement, concrete, stucco (8 colours), city bricks (4), windows (4, opaque) and lit windows (3, light 10, so towers glow at night), roof tiles, metal sheet (6), shop signs (16 pixel icons, one per trade) and sign bands (8 colours); plus roof stairs and slab, awning, steel, steel post (a fence shape), light panel (a light-emitting slab), counter, shelf, crate, bin, mailbox, job board, till, vault door and a traffic cone. Items 354–363: foam bopper, cream pie, disguise kit, burger, donut, fizz pop, coin, coin purse, gold watch, swag bag.

### Residents (`shared/city/people.ts`, `sim/city-watch.ts`, `client/city/crowd.ts`)

- 672 named residents for the default map: two to a house, six to a block of flats, twelve officers who live at the Watch House. Each has a job at a real place (two keepers for every counter, office workers, yard hands, couriers, gardeners, stallholders, buskers, sweepers, cabbies, medics, crew; about a third have none and stroll), a look (skin, hair, clothes, a hat or their trade's uniform), a walking pace and a temperament (15 % brave: they bonk back; 20 % snitches: they see twice as far).
- A resident's day is a pure function of `(seed, resident, day, time)`: stays (home, the counter, a bench, a lunch counter) joined by walks along the sidewalk graph (four corner nodes round every block, crosswalks between blocks, a Dijkstra tree per source node kept once built). Walkers keep right of the sidewalk's middle so opposite flows pass. Keepers work two shifts (06:30–16:00 and 15:45–02:00), so a place is open exactly while `placeOpen` finds a keeper at its counter. Officers walk a beat round one block within three of the Watch House in three shifts; couriers call at doors and return to the depot; office workers go out for lunch at noon. Every day starts and ends at home with no teleport between steps (tests check both).
- Because the script is a function of time, **nothing about an undisturbed resident is simulated or sent**. Every client draws the residents near its camera from the same function: one instanced mesh per body part (about a dozen draw calls for up to 176 figures, coloured per instance), walking, working, busking and looking at whoever comes near. The server evaluates a tenth of the roster a tick into a 16-block grid (`refreshCrowd`) for witnesses, traffic and collisions, and exactly (`whereIs`) when a command names a resident. Far from players they cost nothing.
- A disturbed resident becomes **live** (`goLive`): bonked (dizzy with stars, then fleeing, or squaring up if brave), fleeing as a bystander, dodging or being hit by a fast vehicle, stopping to talk, or an officer in pursuit. Live residents are simulated with the mobs' body physics (`moveBody`), sent to seats within 72 blocks as `[index, x, y, z, yaw, state]` and drawn in place of the script; afterwards they walk back to where the script has them and drop off the wire. Extras (reinforcement officers, a driver turfed out of a car, a cab fare at the kerb) are numbered past the roster (`EXTRA_OFFICERS` further for officers, so screens know the uniform). Officers path with the shared A* (three plans a tick).

### Vehicles (`shared/city/vehicles.ts`, `sim/city-rides.ts`, `client/city/rides.ts`, `scene.ts`)

- Sixteen kinds (`RIDES`, append only; the last six are the second helping's: a free city bike, the Trundler bus, the Big Squirt fire engine, the Patch Wagon ambulance, a dinghy and a speedboat). The first ten: Zipster scooter, Pebble hatchback, Lugger pickup, Breadbox van, Hopper cab, Zinger coupé, Hornet motorbike, Watch cruiser, Dragonfly helicopter and Puddle Jumper plane, each with size, seats, top speed (14–30 blocks a second), acceleration, braking, grip, turning circle and price. Models are code-defined boxes (painted parts take one of eight colours, trim keeps its own), instanced per kind, with wheels, rotors, a rider on two-wheelers and a flashing bar on cruisers.
- **Driving is the player's body with different physics.** While a seat drives, its client steps the shared `stepRide` at 60 Hz (throttle, brakes and drag; steering by a bicycle model limited by grip; two square probes at nose and tail swept through the voxel world; a one-block climb for kerbs, after which the vehicle is set straight down on the step, so a stunt ramp, which is a flight of such steps, can be taken at full speed; the helicopter and the plane fly) and sends the vehicle's pose as its own position with the velocity. The server checks it against that vehicle's envelope (`Player.pace` = the kind's top speed in the walking budget, `Player.aloft` lifts the no-climbing rule, no fall damage, the city's bounds) and copies the driver's accepted pose onto the vehicle. Enter and exit are commands answered with a teleport (and a yaw), so both sides switch physics at the same instant. Passengers are carried by the server and send no position. The driver's screen bounces off other vehicles itself; the camera is a chase camera that swings back behind when left alone and pulls in from walls.
- Parked vehicles come from the plan's 1,776 kerb bays (9–16 % filled by district) and fixed bays (two scooters on the spawn plaza, cruisers at the Watch House, vans at the depot, the dealer's forecourt, cabs at cab stands, aircraft at the airfield), stood in their bays within 96 blocks of a player and cleared when nobody is within 128. A taken bay stays empty for the session; an abandoned vehicle is cleared after 150 s with nobody near.
- Traffic runs on lane rails between intersections, only round players: up to six cars each (four in rooms over 24, capped at 20 + 5 a player, 140 at most), spawned 68–112 blocks away out of everyone's sight. A car follows its lane, turns on a curve through the intersection (one car at a time holds it), brakes for vehicles, players and residents ahead and sounds its horn at a player in the road. A cruiser is traffic that steers for its quarry and lets two officers out near a quarry on foot. Pulling a driver out of a slow traffic car is always witnessed (by the driver).

### Networking additions (`shared/protocol.ts`, `sim/city.ts`)

- `Settings`: `mode: 'city'`, and only then `minutes: 0 | 10 | 20 | 30` and `bonks: boolean`, so survival and creative settings keep their shape.
- `WireScene` gains optional `c` (live residents) and `v` (vehicles: `[id, kind, x, y, z, yaw, paint, flags, speed, pitch]`); parked, empty vehicles (`RF.ASLEEP`) are included once a second per screen. The client takes that list the moment a scene arrives (`Rides.park`), not from the two scenes a frame is drawn between, and keeps it until a newer list replaces it: a screen drawing fewer frames than the server sends snapshots would otherwise rarely be between the one snapshot a second that carries the list, and parked vehicles blinked out (found on a software-rendered QA page, true of any slow phone). A playing screen that has had no list for 2.5 seconds says so in its input (`IF.PARKED`, the eighth input flag) and the server lists them in every scene until the flag drops, the same idea as the bag's revision: a screen cannot miss the list for long however few frames it draws. The TV sends no input and keeps the once-a-second cadence. `View.city` (about once a second): the scoreboard `[seat, coins, heat tier, net worth]`, the round clock and the newest news line; `View.ledger` once finished. `PrivateView.city`: coins, heat, whether an officer has eyes on you, the arrest in progress, the vehicle ridden, the gig, the open counter or board and its offers, what is owned. Player flags gain `RIDING` (the body is not drawn) and `DIZZY`.
- Results: `View.ledger` is one row of twenty numbers per seat in `LEDGER_KEYS` order, and it is a **cached field** of the view (`manifest.snapshotCache.fields`), so it is sent once, when the round ends (`finishCity` moves `revision`), and left out of the snapshots the results screen repeats. Once a city round has finished those snapshots also drop everything of the streets (`cityOver` in `sim/views.ts`: no roster, TV feed or scoreboard in the public view, no surrounding scene or pockets in the private one), because nobody is looking at them behind the ledger, and the outcome's own rows (a 36-character player id and a score for every seat, 4 KiB at 64) are left empty once the round is over, because `CityResults` ranks from the ledger it was sent once (`cityOutcome`; winners are named only when four or fewer lead with more than the starting coins). What is left is about 0.6 KiB a snapshot whatever the size of the room, which a test holds under 0.9. The rest of this paragraph is the history of why. Originally the ledger was eleven numbers per seat in `LEDGER_KEYS` order (`decodeLedger` puts the ids back from `who`), the outcome rows carry only an id and a score, and city results leave the wild's journal out. The room server repeats the results snapshot at the snapshot rate for as long as the results screen is up, with the whole outcome in each one, so every byte in it is paid twenty times a second: the first version (an object per player, the journal as well, a label per outcome row) came to about 30 KiB a snapshot at 64 players, 430–570 KiB/s to each screen as measured on a real server. As built a results snapshot at 64 is about 15 KiB (6 KiB of public view, 5.5 KiB of outcome, 3.8 KiB of private view), still some 300 KiB/s; what is left is the platform's repetition, which this game cannot change (the wild's results are 22 KiB at 64 by the same sum).
- One new command, `{ t: 'city', a, i, j }` with `a` in `CITY_ACTS` (exit, horn, open, shut, buy, sell, gig, quit, call, scrap…; the second helping appends give, spot, say, cell, stall, wear, biz and tune). Bonking and talking reuse `attack` and `interact` with ids from `CITY_ID` (2³⁰, residents by index) and `CITY_PLAYER_ID` (players by seat); a vehicle is targeted by its entity id; `use` on a job board opens it and mining a till grabs it. `cityCommand` runs before the ordinary rules and returns null to let them through (inventory, eating, dropping, building on an owned plot).
- Cost: the plan and the scripted crowd are free on the wire. Measured with `tools/scale-bench.ts --mode city`: a private view is about 0.5 KiB, a phone receives 19–22 KiB/s with 32 or 64 players spread over the city and 33–47 KiB/s with everyone on the plaza; the tick is 1.0–1.2 ms median spread (0.3–0.4 packed), with about 320 vehicles in existence. On a real server with socket bots, half of them driving: 27 % of one core and 21–24 KiB/s a phone at 32, 37 % and 25–31 KiB/s at 64 (the README has the table).

### Second helping (2026-11-22): more to do, more of it together

The owner's brief: the city was "pretty cool but somewhat limited"; make it a place a group can spend an evening in. Played first as a newcomer on a phone-sized page, the city ran out in about ten minutes: three kinds of gig that are all "walk to a door", six things to buy, nothing two players could do to or with each other but bonk, districts that were scenery, and nothing on screen saying what there was to try. What was added, in the order a new player meets it:

- **The City Passport and the to-do card** (`shared/city/passport.ts`, `sim/city-career.ts`, `client/ui/city-extra.tsx`). 32 stamps, one for each thing worth trying. A stamp is a bit in the player's saved record, pays a few coins once, and the first three a player has not got are a card on their HUD (hidden while a gig, a race or Heat needs the space); a tap opens the passport, which says how to get each. Titles come with the count (Newcomer → Legend) and go in the news. This is the whole of the onboarding: there is no tutorial. A stamp earned by something that has just said its own piece ("Resprayed red.", "Parcel round done: 62 coins.") is sent as a second line of that toast, not in place of it (`stamp()` joins a toast made since the tick began; the HUD shows each line as its own notice), and the HUD now shows the first toast of a session, which the wild's hook used to take for a stale one: for a newcomer that is usually their first stamp.
- **The city's own first-person hand** (`client/city/hand.ts`): the sleeve and mitten of the city figure other players see, with its own motions (a bop, a lob, a munch, a rod held out, a canopy's lines). The wild keeps the hand it had.
- **Gadgets** (`sim/city-fun.ts`): water balloons (soak whoever is near, officers splutter, fires hate them), banana peels (an item entity nobody can pick up; the next officer, runner or player to tread on it goes flying), smoke puffs (the Watch cannot see into or out of the cloud and officers on your heels lose the scent), a parasol, a kazoo and a fishing rod beside the pies and disguise kits. A pie can now hit a player.
- **Parachutes**: stepping out of an aircraft in mid-air grants a canopy for 40 s; a parasol in the pockets is a canopy for good. The client opens it when a real fall begins (faster than a jump's landing), clamps the fall to 3.4 blocks a second and says so in its input (`IF.CHUTE`, bit 256: input flags are now ten bits wide); the server believes the flag only while the player may glide (`mayGlide`), moves the fall's peak down with them so landing is soft, and sets `PF.CHUTE` so other screens draw the canopy (`client/city/props.ts`).
- **Six more vehicles** (`shared/city/vehicles.ts`): city bikes in racks at the plaza and wherever people gather (free: no mischief for riding one), the Trundler bus, the Big Squirt fire engine and the Patch Wagon ambulance at their stations, a dinghy and a speedboat at moorings along the pier. Boats are `sea: true`: `stepRide` floats them at `SEA_Y`, lets them go only where the top water cell is open (the beach's shallows and the pier's deck stop them) and never climbs. Stepping out of a boat puts the player on the nearest dry footing within four blocks. City bikes and service vehicles are stood back in their bays 100 s after being taken; other bays stay empty for the session as before.
- **New places, without moving an old one** (`shared/city/plan.ts`, `buildings.ts`, `gen.ts`). Lot numbers are in saves (a flat is a lot), so the zoning map did not change: two of the yards' sheds became the fire brigade and the bus depot (the same lots under other roofs), hat shops joined the rotation of trades in shop blocks, the clinic and the airfield gained job boards, and three lots were appended after the airfield for things outside the grid (`plan.field`, `plan.pier`, `plan.isle`): the pier (now with a wide head, the Brine & Bait hut on it and moorings down its east side) and **Gull Rock**, an island 80 blocks out in the bay with a lighthouse, a shack, a jetty and a landing pad, reachable only by boat or air.
- **Extras** (`shared/city/extras.ts`): the things a player can do something at that are not a counter, all a pure function of the plan like everything else, so the generator, the server and every screen agree with nothing sent or saved. `spots` (four race starts, the spray pad, the bank's alarm bell and vault, the lock-up's lock, three funfair stalls and the prize booth), `courses` (the races, as intersections of the grid), `ramps` (four stunt ramps on the quays and the airfield apron, a block up every three along) and `feathers` (forty golden feathers: sixteen on the roofs of shops and flats with fire escapes, the rest in corners from the bank's vault lobby to the lighthouse gallery). A spot is used with one command (`city` `spot`, i = its index); on foot it is the yellow context button, from a driving seat a second button (G).
- **Professions** (`sim/city-work.ts`, `GIGS` 3–5): **bus routes** (four stops in a Trundler, the last back at the depot; each friend riding along adds a fifth to the pay and is paid for coming), **ambulance runs** (fetch a patient lying out in the city in the Patch Wagon and bring them back to the clinic) and **fire calls** (the call starts a fire; it is paid when the fire is out). Each wants its own vehicle (`DUTY`), which is no mischief to take while that gig is in hand and is restocked by its board. Job boards now pick their three offers from the doors that actually lie in each distance band (the old random sampling came up empty at the corners of the map). A **cab fare**'s passenger now waits outside a place 40 to 160 blocks from the stand, and the clock covers the drive out to them as well as the ride (`GigOffer.pick`; the first version stood them anywhere in the city on a clock that covered only the ride, which nobody had played). A bus route's clock assumes 4.5 blocks a second with four stops to make, not 6.5.
- **Pastimes that pay** (`sim/city-jobs.ts`): **fishing** (Use with a rod facing water casts; the float dips after 2.5–9 s and Use within 1.3 s lands it; six catches by depth of water, sold at the bait hut for the listed price or at any diner for four fifths), **busking** (each kazoo note warms the tune; residents in earshot stop to listen and tip more as it warms; a pitch is played out after about 90 coins), **stunt jumps** (a wheeled vehicle that leaves the ground and lands six or more blocks on pays three coins a block; off a quay ramp at full throttle a scooter flies about 7 blocks, a cab 10, the Hornet 12 and the Zinger 13, which is what the stamp at ten and Old Sprocket's eight and twelve are set against) and **golden feathers** (walk into one: fifteen coins and a bit in the record).
- **Things to own**: **hats** (ten, worn in place of the cap; the hat travels in the first armor field of the player tuple, which the city never used), **businesses** (the counter of any food, gadget, hardware, pawn, cab, hat or bait shop sells the shop itself, once: it pays its owner every minute and three tenths of whatever other players spend there, counts towards net worth, and its owner loses a payout when another player empties its till; three at most a player, saved as place numbers), a **tune-up** at the dealer (an owned vehicle kind is 12 % quicker for good: `Ride.tuned` on the driver's screen, `Player.pace` on the server) and a **respray** at the Spray & Pray pad (a new colour, and 35 heat off a driver nobody is watching).
- **Standing** (`Rep`: townsfolk, the Watch, the Magpies, 0–100 each, packed into one saved integer): gigs, busking and good deeds please the town (10 % then 20 % off at its counters); arrests and bonked officers displease the Watch (a friend of the Watch is waved off without a ticket, an enemy pays a quarter more in fines); fenced loot, till jobs, escapes and the vault please the Magpies (pawn shops pay their friends up to a quarter more). A till emptied in front of somebody makes every shopkeeper wary for three minutes (prices up a quarter). After dark witnesses see about half as far.
- **Together** (`sim/city-play.ts`): **street races** (drive up to a chequered flag post and start one; others have 20 s to join for a 10-coin stake; flags are intersections taken in order; the purse grows with the course and the field; alone it is a time trial for half), **bounties** (whoever the Watch wants most, at Wanted or above, is marked on every map with a price; a player who bonks them collects it and the wanted one goes to the lock-up; off when the room's bonk rule is off), the **Golden Gull** (keep-away: whoever holds the gull earns two coins a second and cannot use a vehicle; a bonk takes it, whatever the room's bonk rule; it flies off after 150 s and the longest holder is named), the **bank vault** (cracking takes 22 s of standing at the vault divided by the number cracking; the alarm rings 7 s in unless somebody stands holding the bell outside; when it opens six gold bars are on the floor, the vault shuts on a six-minute time lock, and a crew whose alarm never rang is still Wanted for the missing gold), **the lock-up** (an arrest now puts the player in a cage on the Watch House forecourt with the fine still to settle: pay it, take community service (no fine, the next gig is unpaid), sit out 40 s for half, or be sprung for nothing by a friend who works the lock for four seconds and is Wanted for it) and **giving** (the context button on another player hands them ten coins).
- **A city where things happen** (`sim/city-events.ts`): every 75–120 s the timetable starts something nobody asked for, different from the last: a **parcel spill** (ten parcels along a pavement, twelve coins each to whoever picks them up), a **crate drop** (first there opens it: coins and a gadget), a **fire**, a **half-price sale** at one shop, a **blackout** (eyes carry half as far for a few blocks) or, with two or more players, the **gull**. Every screen is told in a toast and the news, and events travel in the scoreboard (`CityView.ev`: kind, place, seconds left and two numbers) so maps, the hovering marks in the street and the TV all read one list.

- **People with errands** (`shared/city/story.ts`, `sim/city-story.ts`). Seven characters stand in their own corners (Granny Marrow in the park, Mayor Plumley on the plaza, Old Sprocket at the scrapyard, Fingers McGraw in the market, Captain Peg at the Watch House, Dockmaster Brine on the pier, Madame Fizz at the funfair): a pure function of the plan, drawn by the crowd renderer with their own looks and a green mark overhead while they still have something to ask. Each has three or four errands, each a little more than the last, with its own lines. An errand is a number to reach on a total the city already keeps (gigs, fish, tips, blocks driven or flown, feathers, net worth, a particular stamp), counted from the moment it is taken; one is in hand at a time (`PrivateView.city.errand`, a chip on the HUD) and it pays where it was given. What is saved is how many of each character's errands are done: three bits a character in one integer. Finishing an errand moves the player's standing with that character's group, so the Watch's captain and the Magpies' fixer pull in opposite directions.
- **The funfair** (`sim/city-story.ts`, the `stall` and `prize` spots). Three stalls at Strand Funfair cost five coins a go and pay in tickets (an item): High Striker and Tin Can Alley are a marker to stop at the right moment (the client sends where it stopped, 0–1000, and the server scores it), Lucky Dip is luck. The prize booth swaps tickets for candy floss, a plush gull (the pawn shop buys it) or two hats no shop sells cheaply. Tickets cannot be bought, so nothing here is a wager for coins.
- **The TV** (`client/ui/city.tsx`, `client/game/camera.ts`, `runtime.ts`). The newest headline is a banner across the top for a few seconds before it joins the ticker; a **Happening now** list names the races forming and running and every event with its clock, and the same events are marks on the map; under the three most wanted a board **turns** every few seconds through richest, most stamps, best angler, race wins and longest jump (boards with nothing on them yet are skipped; the columns ride in the scoreboard rows). The spectator camera is told how fast its subject is going: above walking pace it takes a chase shot from behind (`chasePose`) and holds on tighter the quicker the subject is, so it no longer trails a vehicle. A cut to a far corner of the city lands before that corner is meshed; the runtime says so (`hud.cutting`) and the display covers the gap with an "Over to <name>" card naming the district until the ground round the camera is drawn.
- **Touch.** Drop is not offered from behind a wheel. In the air Down sits beside Up (it used to share a corner with the horn). A phone on its side that is not in full screen keeps the room's header, which leaves the game about 250 px of a 320 px screen: the touch layer is a size container, and under 290 px the action cluster closes up so Sneak clears Items and the menu button. The yellow prompt wraps onto two lines before it reaches the action buttons.

How it travels. Everything a player has made of the city (`Career`: stamps, feathers, errands, standing, look, businesses) rides in the bag, which is sent only when it changes, so the steady private view grew only by what is happening right now (a race, a line in the water, a hold, the lock-up). Events and races are in the once-a-second scoreboard. The ledger moved into the snapshot cache (above). New effects are FX kinds like the old ones.

### Limits and what is not there

- Aircraft: the helicopter and the plane are implemented in `stepRide`, stand at the airfield and can be bought there. A pilot who steps out in mid-air floats down under a canopy (the second helping); an aircraft with nobody aboard has no lift and settles onto whatever is under it at seven blocks a second (`Vehicle.sink`), sent as a moving vehicle until it lands.
- The TV follows whoever is hottest, or takes turns. Its chase shot and the cover card for a cut across the city (the second helping) were judged only on a software-rendered QA page drawing a few frames a second; neither has been seen on a real television.
- Vehicles do not push players or each other on the server (the driver's own screen stops at other vehicles); officers arrest on foot only; there are no traffic lights; cars queue at intersections one at a time.
- Remote vehicles are interpolated like everything else (100–190 ms behind) with no extrapolation.
- The city is one fixed map: seeds change its dressing, not its streets.
- What is in hand is not saved: a gig, an errand taken but not handed in, a race, a stay in the lock-up, Heat, and whatever the city has going on. A loaded city starts quiet with everyone free; what a player has made of it (the 28 numbers) is all that comes back.
- The seven characters stand where they are put: they have lines and errands, not routines, and they cannot be bonked.

## Quality bar and validation

- `node --import tsx --test packages/games/blockwild/tests/*.test.ts`, `npm run typecheck`, `npx oxlint packages/games/blockwild` (scoped), and `npm test` for the platform contract tests must pass.
- Browser QA uses `npm run build:isolated -- <unique-name>` and `HOST=127.0.0.1 npm run serve:isolated -- <name> <port>` with headless Chromium and software WebGL (slow; judge visuals, not fps). For anything visual, the sandbox is quicker: `npx vite --config packages/games/blockwild/dev/vite.config.mjs --host 127.0.0.1 --port <port> --strictPort`, then `http://127.0.0.1:<port>/games/blockwild/?scene=pasture&time=6000&freeze=1` (the real scene and HUD driven by the simulation in the page; `view=tv`, `players=64&scene=crowd`, `yaw`, `pitch`; see `dev/sandbox.tsx`).
- Big rooms: `node --import tsx packages/games/blockwild/tools/scale-bench.ts --players 10,32,64 --layout cluster|spread|fly` for tick time and bytes per screen without a server; `tools/room-host.ts` plus `scripts/qa/room-bots.ts --hook packages/games/blockwild/tools/room-bot.ts` for a real server with real sockets.
- Real acceptance: a solo host plays (walk, mine a tree, craft planks/table/pickaxe, mine stone, place blocks, night falls, torch glows), 2-player co-op sees each other and each other's edits, and a 32-player room (a real display, a real phone and socket bots) keeps the HUD/TV readable; 64 is exercised with bots and the sandbox. Results and replay work.
